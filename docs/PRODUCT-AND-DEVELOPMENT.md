# 技能开工站：产品与开发交接

## 1. 产品定位

技能开工站不是 GitHub 链接搬运站，而是中国 Codex 用户的 Skill 决策入口：

1. 用中文描述工作。
2. 找到最少且合适的 Skill。
3. 看懂来源、依赖、权限和风险。
4. 复制安装方法或 Codex 任务单。

## 2. 本次设计修正

旧方案的主要问题：

- 页面功能过多，搜索、排行榜、体检、组合、更新、教程同时抢首屏注意力。
- 蓝紫渐变和大量相同卡片容易产生通用 AI 模板感。
- 演示 Star、安装量和质量分容易让用户误以为是真实数据。
- “来源已核验”“人工测试”“安全”之间的边界不够清楚。
- 商业入口缺少真实地址和条款时仍表现成可点击服务，会削弱信任。

本版调整：

- 首屏只保留一个任务搜索和一个开工流程示例。
- 使用温暖纸张、深墨绿和单一朱红强调色，形成中文工具书气质。
- 列表使用真实来源，不展示未取得的数据。
- 详情页把“能做什么、不能做什么、要准备什么、会访问什么”放在安装之前。
- AI 工作台先实现纯前端任务单生成，不把用户内容提交到服务器。
- 商业入口在真实链接、主体、条款和隐私说明齐全前明确标记为待配置。

## 3. 页面

| 路由 | 用途 |
| --- | --- |
| `/` | 任务搜索、分类、首发精选、产品方法 |
| `/skills` | 搜索、分类、来源和小白筛选 |
| `/skills/[slug]` | 决策、安装、权限、话术、源地址 |
| `/workbench` | 本机 Codex 任务单生成器 |
| `/guide` | Skill、插件、安装位置和安全指南 |
| `/services` | 第三方商业服务透明预留 |
| `/privacy` | 当前版本隐私说明 |
| `/terms` | 使用边界 |

## 4. 数据结构

首发数据位于 `app/data/skills.ts`。新增条目必须至少具备：

- 中文名与原始名
- 一句话用途
- 用户任务别名
- 来源类型、仓库和具体 GitHub 路径
- 难度和权限提示
- 适合人群、输出、能做与不能做
- 使用前准备
- 可复制任务话术
- 核验日期（当前在站点级展示）

禁止录入：

- 无来源的 Star、安装量、收藏量和质量分
- 未完成隔离测试却标为“已人工测试”
- “绝对安全”“官方推荐”等无法证明的结论
- 未核验的安装命令

## 5. 下一阶段

正式内容系统建议按以下顺序扩展：

1. 后台审核队列与版本化内容。
2. GitHub App 元数据同步。
3. 静态权限扫描结果与证据。
4. 失效链接和更新时间监控。
5. 中文同义词搜索统计。
6. 在明确同意和隔离环境下进行运行测试。
7. 最后再增加排行榜、对比和更新订阅。

排行榜不能只依据 Star。质量、热度、测试状态和来源可信度应分开展示。
